Graphectory API

Turn a recorded coding-agent run into a Graphectory trajectory graph by sending the file over HTTP.

Graphectory converts an agent trajectory into a directed multigraph: each node is a distinct action (tool, command and arguments; repeated actions merge into one node, so loops show up as cycles), and edges follow the order the agent took them in. Each action is labelled with a problem-solving phase: localization, patch, validation, plan, general.

The API is stateless: the file is analysed and the graph returned; nothing is stored and the dataset shown in the viewer is not changed. It is served on this server's private Tailscale address only.

Base URL: https://<this server>

Quick start

Send the file with --data-binary @file (not -d, which strips newlines and breaks JSONL).

BASE=https://<this server>

# A SWE-agent .traj → the interactive graph page
curl -X POST -H 'Content-Type: application/json' \
     --data-binary @django__django-10973.traj \
     "$BASE/api/analyze?id=django__django-10973" -o graph.html

# A Claude Code session (JSONL) → the graph as JSON
curl -X POST -H 'Content-Type: application/x-ndjson' \
     --data-binary @session.jsonl "$BASE/api/analyze?format=json"

# An OpenDraco multi-agent run → run view + one graph per agent
curl -X POST -H 'Content-Type: application/x-ndjson' \
     --data-binary @run.jsonl "$BASE/api/analyze?agent=opendraco" -o run.html

Python

import requests

with open("run.jsonl", "rb") as f:
    r = requests.post("https://<this server>/api/analyze",
                      params={"format": "json"}, data=f,
                      headers={"Content-Type": "application/x-ndjson"})
r.raise_for_status()
graph = r.json()

BodyThe raw trajectory file, unmodified.
Content-Typeapplication/json for a single JSON object; application/x-ndjson (or application/jsonl) for one JSON record per line. Anything else → 415.

  "agent_type":  "sa",                     // detected or forced format

  "graph": { … }                           // networkx node-link data, see below

Graph JSON schema

graph is networkx node-link data for a MultiDiGraph: {"directed": true, "multigraph": true, "graph": {…}, "nodes": […], "edges": […]}. Some values may be strings where the builder stored non-JSON types.

graph (metadata)

instance_nameThe trajectory's name.
resolution_statusnone here (no evaluation report is attached to an upload).

Node fields

id"<index>:<label>"
label, tool, command, subcommandThe action, e.g. str_replace_editor: view, or the shell command name.
args, flagsParsed arguments and flags.
phasesOne phase per visit: localization · patch · validation · plan · general.
step_indicesThe agent steps (0-based) that ran this action; several when revisited.
observation_outcomesuccess · failure · neutral: how the tool output looked.
observation_length, observation_lengthsOutput length, total and per visit.
thought_len_raw, thought_len_clean, thought_lengthsLength of the reasoning before the action.
has_cdA leading cd was stripped.
step_dataPer visit: {step_idx, thought, action, observation}, the full text (can be large).

Edge fields

source, target, keyNode ids, and the edge's key within the multigraph.
typeexec: execution order (label = step number) · step: sub-actions chained in one step (e.g. a && b) · hier: path hierarchy between file views.
is_first_in_stepFirst action of its step.
thought_length_raw, thought_length_cleanReasoning length carried by the edge.

OpenDraco multi-agent runs

An OpenDraco run is several agents handing work to each other, recorded in one runs/<run_id>/run.jsonl. The response holds one ordinary graph per agent plus a run view of how they worked together.

Per-agent graphs

  • Each agent's turns, in local_turn order, become one trajectory built by the same builder as Claude Code sessions, so phases, outcomes and metrics match the other formats.
  • thinking, and any message before a tool call, are the step's thought. tool_call + tool_result is an action and its observation, paired within one activation (models reuse ids like call_0).
  • The last message of a turn that calls no tool is a final_answer action.
  • The deliveries that started a turn open its first thought as from <agent>: <value>, or from the parent run for a fork.
  • Phases: bash goes through the shell rules, with failures read from exit code N, a timeout or tool failure: in the result; read is localization; write is patch, or localization/validation for test paths; web_search is localization; any other tool uses the generic rule.
  • A run still in progress (no run_finished, possibly a half-written last line) is accepted: status is in_progress. After a resume, the abandoned attempt is marked and the rerun is shown.

Run view (HTML)

  • Agents working together: each agent with activations, phase mix, tokens, duration and whether it changed the workspace; delivery edges (count × edge id) and route choices (picked / decisions).
  • Timeline: supersteps × agents, a block per activation and an arrow per delivery.
  • Patterns detected (below), and one tab per agent with that agent's graph.

Multi-agent patterns

Detected from the log's structure alone, with no model involved.

KindFires whenDefault
ping_pongTwo agents hand work back and forth N or more times in a row with no workspace commit in between.N = 4
stalled_handoffAn agent is activated M or more times, never calls a tool or changes a file, and only passes its input on.M = 3
router_churnOne conditional node (route_decision group) picks the same target K or more times.K = 3
hot_agentOne agent takes more than X of all activations or all tokens (needs two or more active agents).X = 70 %

Errors & limits

Errors are JSON: {"error": "<message>"}.

StatusMeaning
400Bad input: unrecognised JSON shape, invalid id, agent, agent_id, format or phases, empty body, no trajectory found.
403Cross-origin browser request.
411Missing Content-Length.
413Body over 20 MiB.
415Wrong Content-Type.
422Valid JSON that the graph builder could not process (a malformed trajectory).
503Both upload slots busy; retry shortly.
Graph building has no hard time limit. A very large trajectory occupies one of the two slots until it finishes.

Security notes

  • The upload is only ever parsed as JSON/JSONL; nothing in it is executed. Shell commands inside a trajectory are parsed to classify them, never run.
  • The file is staged in a private temporary directory on the server's in-memory /tmp and deleted before the response is sent.
  • All trajectory text (thoughts, commands, tool output) is treated as untrusted and escaped in the HTML. OpenDraco agent tabs run in sandboxed frames.
  • The server runs as a non-root user in a read-only container with all Linux capabilities dropped.
